## 1. Deep research (AI-Q pattern)

Send a question → the research server fans out (search → fetch → adversarial verification → synthesis) → cited report. Not a one-shot answer; there's a source trail.

```python
from research_q import deep_research
job = deep_research("impact of EIP-4844 on L2 rollup costs 2024-2026", depth="thorough")
print(job.report)        # markdown + [1][2] citations
print(job.sources)       # list of URLs + the claims they support
```

If the host has a `deep-research` skill harness (Claude/Cursor) → route there. If not → `research_q` runs via `model_registry` + the operator's web fetch. **Every important claim needs a citation**; without a source → mark it "unverified", don't sell it as fact (in line with self-critique sk56).

## 2. Scientific tool workflows (ToolUniverse-style)

Scientific research = a combination of many small tools, not one model. Chain them into a pipeline:

```
QUERY → [literature search] → [fetch papers] → [extract method/result]
      → [cross-check claims] → [stats/replication check] → [synthesize + cite]
```

Pattern: one tool per step with structured output, chained. For specific domains (bio/chem/materials) connect to public APIs/DBs (PubMed, arXiv, Semantic Scholar, PubChem) — keyless or free tier. Cross-verify ≥2 sources before concluding.

## 3. Hypothesis generation & experimental design

```
1. OBSERVATION → what is known? what anomaly/gap?
2. HYPOTHESIS  → a testable + falsifiable statement (not "X might be good")
3. PREDICT     → if H holds, we must see Y under condition Z
4. DESIGN      → control vs test variables, sample size, metrics, baseline, ablation
5. ANALYZE     → the fitting statistical test + significance threshold DECIDED UP FRONT
```

A hypothesis must be falsifiable — if no result could refute it, it isn't a hypothesis. Different from sk57 (hypotheses for *debugging* a system); sk22 = *research/scientific* hypotheses. For experiments on strategies/agents themselves → use variance testing sk56 as the measuring tool.

## 4. Scientific domain libraries & discovery

For applied science, **don't reimplement** — dispatch to existing, validated domain libraries/tools. The agent is the orchestrator + verifier, not a source of biomedical truth.

| Domain | Mature tool/library (examples) |
|---|---|
| Cancer genomics / RNA velocity | `scanpy`, `scvelo`, `anndata` |
| Drug-target binding / docking | `RDKit`, `AutoDock Vina`, `DiffDock` |
| Molecular dynamics | `OpenMM`, `GROMACS` |
| Geospatial science | `geopandas`, `rasterio`, `xarray` |
| Time-series forecasting | `statsmodels`, `prophet`, `darts` |

Pattern: the agent picks the right tool, prepares the input, runs it, **verifies the result** (sanity check + method citation), instead of inventing numbers. 100+ scientific libraries = dispatch targets, not built-in claims.
