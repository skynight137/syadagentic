## 1. MCP-Builder

MCP (Model Context Protocol) = the standard for giving scripts/resources to an LLM host (Claude, Cursor, etc.). Building a server = defining tools + clear schemas.

```python
from mcp_builder import scaffold_mcp
scaffold_mcp("weather", lang="python", tools=[
    {"name":"get_forecast", "desc":"Weather forecast per city",
     "params":{"city":"str", "days":"int"}},
])  # → ./mcp-weather/ : server.py + pyproject + README + run cmd
```

Best practices the scaffold enforces:
- **Sharp tool description** — the host picks a tool from the description; vague = wrong call. One sentence of what+when.
- **Strict schema** — typed params, explicit required vs optional, example values.
- **Errors as data** — return an error message the LLM can understand & retry on, not a raw exception.
- **Idempotent where possible** + no silent side effects.
- **Stdio by default**, HTTP if remote (add auth).

Python uses `FastMCP` (`pip install mcp`); TS uses `@modelcontextprotocol/sdk`. To list/explore existing MCPs → the host has a registry (see also sk0 marketplace for skills, which is different from MCP servers).

## 2. Prompt-Engineer skill

Detect & fix prompt problems systematically, not by guessing:

```python
from mcp_builder import audit_prompt   # prompt tools live in mcp_builder too
print(audit_prompt(my_system_prompt))
# → findings: [ambiguous-instruction, no-output-format, conflicting-rules, no-examples, ...]
```

Checklist of common prompt problems:

| Problem | Symptom | Fix |
|---|---|---|
| Ambiguous | model guesses the intent | be specific + give examples |
| No output format | inconsistent output | define a schema/structure |
| Conflicting rules | model picks at random | resolve the conflict, explicit priority |
| Negation only ("don't X") | model does X anyway | state what it MUST do, not just bans |
| Weak few-shot | fails on edge cases | examples that represent the hard cases |
| Overload | one prompt, 10 tasks | split / chain |

Prompt optimisation loop = **eval-driven** (use sk56): change 1 element → eval → compare pass_rate & variance → keep the winner. Don't change many things at once.
