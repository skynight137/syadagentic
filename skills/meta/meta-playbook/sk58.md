# sk58 — Problem Shaping & Decision Support (SYADAGENTIC)
# Load when: problem shaping, decision support, framing, brainstorm, priority, decision, tradeoff, ambiguity
# Category: Meta & Self-Improvement
A "human-level" skill before execution: turn vague goals into precise subtasks, brainstorm with operator sign-off, and support decisions when information is incomplete. sk53 = technical decomposition/strategy. sk58 = **framing & decisions upstream**, while the problem itself is still unclear.

> Culture note: this is the only cluster that deliberately **slows down** before execution. SYADAGENTIC defaults to "execute first". sk58 only fires when the goal is ambiguous or the stakes are high — not for every task. Don't over-shape tasks that are already clear.

---

## 1. Problem shaping — vague goal → precise subtasks

Operators often state an outcome ("make me money from Web3"), not a task. Shaping is the bridge:

```
1. RESTATE   → rewrite the goal in your own words, confirm in 1 sentence
2. UNKNOWNS  → what isn't known & WOULD CHANGE the plan? (budget, timeline, skill, risk appetite)
3. CONSTRAINTS → hard limits (capital, time, legal, chain, tooling you have)
4. DECOMPOSE → break into subtasks that each have a clear & testable "done"
5. SEQUENCE  → order + dependencies + what can run in parallel (hand off to sk53/sk17 planner)
```

Question rule: only ask unknowns that **change the plan**. Don't interrogate. Max 2-3 questions, once, then proceed with flagged assumptions (in line with R8: no multi-question dump).

## 2. Brainstorming + sign-off workflow

For direction decisions (architecture, strategy, product) — spread options first, don't jump to one answer:

```
1. DIVERGE  → 3-5 approaches from different angles (e.g. MVP-first, risk-first, cost-first)
2. SCORE    → per option: effort, risk, time-to-value, reversibility
3. RECOMMEND → point at 1 + short reason, name the runner-up & when it's better
4. SIGN-OFF → "lock option B?" — WAIT for the operator before big/irreversible execution
5. EXECUTE  → after sign-off, go without asking again (R9: one gate, then execute)
```

Sign-off is mandatory ONLY for the expensive/irreversible (prod deploy, big capital allocation, rebrand). Small/reversible tasks → execute directly, no signature needed.

## 3. Decision support under uncertainty

When data is incomplete (often, in crypto/ops), don't pretend to be sure or freeze up:

```
- Separate: what is KNOWN | ASSUMED | UNKNOWN
- Mark confidence explicitly: "high/medium/low" + what would change it
- Rough expected value when numbers exist: upside × P(up) vs downside × P(down)
- One-way vs two-way door: irreversible → go careful & gather info; reversible → execute fast, learn from the result
- Surfacing risk ≠ refusing. Name the risk + still give a recommendation that can be run.
```

Honest uncertainty output:
```
Recommendation: bridge via Across (confidence: medium)
  known: Across fee < Stargate right now, route is live
  assumed: enough liquidity for 5 ETH (depth not checked yet)
  check first if you want certainty: quote real-time depth → 10 seconds
  reversible? yes (can pick another route) → safe to execute, I'll quote first
```

## 4. Context design

Before complex work, build the right context (not a full dump):
- Pull what's relevant from memory (sk55) + USER.md, not the entire history.
- State assumptions & constraints up front so the operator can correct cheaply before it's built, not after.
