# sk57 — Systematic Debug & Auto-Debug (SYADAGENTIC)
# Load when: systematic debug, auto-debug, root cause, trace, stack trace, step through, isolate bug
# Category: Meta & Self-Improvement
Structured 4-phase debug + an automatic hypothesis loop. sk54 = error pattern library (fast, lookup). sk57 = the method for bugs **not in the library** — the weird, intermittent, or deep ones. Load sk57 when sk54 stalls or the bug is non-trivial.

---

## 4 phases (in order — don't jump to Fix)

```
1. RCA        → Root Cause Analysis: reproduce → isolate → find the root, NOT the symptom
2. PATTERN    → match against known patterns (sk54 library, previous errors in memory/sk55)
3. HYPOTHESIS → form TESTABLE guesses, ranked by likelihood × cheapness-to-test
4. FIX        → test hypothesis #1; right → patch + regression test (sk56); wrong → hypothesis #2
```

Fatal anti-pattern: guessing a fix without reproducing. "Try a restart / add try-catch" without knowing the root = covering the symptom, the bug comes back.

## Phase 1 — RCA

```
- Reproduce first. Can't reproduce → collect conditions (input, env, timing, state).
- Isolate: bisect (comment out half / git bisect), minimal repro case.
- Ask "why" down to the root: error X → because Y → because Z. The root is Z, not X.
- Evidence, not guesses: logs, stack trace, state dump, KQL (sk21), eth_call revert reason.
```

## Phase 2 — PATTERN

Match against what's already known before thinking from scratch:
- sk54 library (nonce too low, RPC timeout, duplicate webhook, etc.).
- Memory/sk55 — "has this error come up before?" (reinforced lesson).
- Classic symptoms: race (intermittent), off-by-one (boundary), stale cache (sometimes right sometimes wrong), env drift (runs locally, fails in prod).

## Phase 3 — HYPOTHESIS (the core of auto-debug)

```python
from eval import variance   # reuse for flaky bugs
# Frame hypotheses as testable statements + the cheapest way to test them
hypotheses = [
  {"h":"ankr RPC rate-limit under burst", "test":"swap to llamarpc, retry 20×", "cost":"low", "p":0.6},
  {"h":"nonce race across parallel wallets", "test":"serialize 1 wallet, repeat", "cost":"low", "p":0.3},
  {"h":"gas estimate short during spike", "test":"raise buffer 2×, repeat", "cost":"med", "p":0.1},
]
# sort by p × (1/cost) → test the cheapest-most-likely first
```

Auto-debug loop:
```
WHILE the bug is unexplained:
  pick the hypothesis with the highest (likelihood × cheap-to-test)
  run the test → observe
  confirm → go to FIX
  refute → discard, update the prior on the others, continue
  all exhausted → generate new hypotheses from the latest evidence (don't cling to refuted ones)
```

For **intermittent** bugs: use `variance()` (sk56) — run N times, look at the failure mode distribution. A bug that shows up 2/10 = a race/timing/rate-limit signal.

## Phase 4 — FIX

```
- Fix the root, not the symptom. If only the symptom is reachable → mark it + log why (don't stay quiet).
- Add a regression test (sk56 Eval) — the same bug must not come back silently.
- Reversible & operational (RPC/retry/cache) → may auto-fix (sk55 SAFE_AUTO_ACTIONS).
- Touches skills/funds/rails → proposal (frozen-paths), operator ack + re-lock.
- Record to memory (sk55): symptom → root → fix. Next time it becomes an sk54 entry.
```
